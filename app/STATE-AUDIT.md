# Shader Studio state and invariant audit

The audit covers the editor, library, profile and authentication, AI chat and provider adapters, composition and preview, media and export, Figma sync, and Supabase persistence. It follows state through browser storage, React, the GPU runtime, Supabase queries and RPCs, object storage, and the two Edge Functions. It includes older saved documents, delayed requests, interrupted streams, navigation during work, and multiple tabs. The findings describe the code paths examined and the behaviors established by local tests.

## Durability follow-up

- The new document commit RPC saves source, parameters, media references, editor metadata, and the checkpoint in one transaction. The editor stages thumbnail and media uploads before committing their references. Revision and timestamp checks reject stale writes, including writes from an older client that only changed metadata. Checkpoints now record title, description, and visibility at the time of the commit. Restore retains its existing visual-only behavior.
- Owned plans have an exclusive lease per shader and plan revision. The built receipt commits alongside the compiled source and agent checkpoint. Failed builds can release the lease, and abandoned leases expire. Historical cloud build markers remain readable. Drafts keep the existing local plan behavior.
- Published shader references are enforced by foreign keys. A transaction can publish the parent and its eligible owned dependencies together. A direct write, including one from an old client, cannot make a referenced shader private or delete it while a public parent still references it. The migration backfills valid existing references and preserves the visibility of legacy rows that already have missing references.
- Draft promotion uses the deterministic shader ID for the save lock and preserves the local draft if its persisted record or active editor changed during the upload. Automatic migration leaves a divergent cloud copy and local draft available for the user to reconcile. The Figma linkage update uses revision and timestamp checks and only changes active editor state for the shader that initiated the operation.
- Cloud Storage uploads and deletions still run outside the database transaction. Failed uploads can leave unreferenced objects, and thumbnail cleanup needs a durable retry queue. An upstream Figma create with an unknown outcome still needs reconciliation. Whole-record chat/draft storage and provider-side behavior still need separate work.

The migration was exercised on disposable PostgreSQL with two independent clients, with minimal Auth and Storage schemas to run the repository migrations. The browser regression delayed the plan checkpoint and reopened the editor in an independent session. Hosted Supabase, Storage policies through the live API, and external Figma creation still need staging verification. Apply the migration before shipping the frontend that calls it.

## Original high-priority findings and remaining work

| Priority | Boundary and current assumption | Recommended fix | Acceptance case |
| --- | --- | --- | --- |
| P1 | **Cloud save and version history.** Source and parameters commit through the revisioned RPC. Name, description, visibility, Figma links, and asset metadata can commit in later writes. A partial failure can leave the row and its checkpoint describing different states. A same-revision metadata write can race another metadata writer. See `App.jsx`, `services/shaders.js`, and the latest `save_shader_state` migration. | Stage media first. Commit document fields, metadata, and the requested checkpoint through one revisioned RPC. Return the committed revision and operation ID. Keep asset cleanup retryable after commit. | Fail each network request in turn. Reload and verify the visible shader and its checkpoint reference the same committed snapshot. Try concurrent metadata-only saves. |
| P1 | **Publish, unpublish, and delete.** Client graph scans and visibility checks run before mutations. A second client can publish a dependent item between the check and commit. Public thumbnail publication and cleanup happen separately. See `App.jsx` and `cloudCompositionGraph.js`. | Maintain indexed dependencies and enforce public graph rules in a database transaction shared by all three operations. Lock affected rows in a stable order. Stage final media and thumbnails before visibility is committed. Enqueue exportable cleanup records for retries. Define retention for pinned dependencies separately from live references. | Race parent publish against child unpublish and delete. Inject failures before and after visibility commit. The public view is usable or the action fails with a specific dependent reference. |
| P1 | **Draft promotion.** Deterministic IDs permit retry, but browser tabs can still promote the same draft concurrently. Local draft, plan, and media cleanup is not tied to an acknowledged local draft revision. Edits made while the first upload runs can be left without the matching local recovery record. See `cloudDraftPromotion.js` and `draftPromotionCleanup.js`. | Lock or claim promotion by draft ID, record the local revision and cloud revision, and remove only the local revision that was acknowledged. Move later edits to the new identity with durable recovery intact. | Type during a blocked upload, reload immediately after promotion, and compare the recovered edit. Promote concurrently from two tabs. |
| P1 | **Plan build durability.** Built markers are written independently from the queued shader checkpoint. Two tabs can both see a ready revision, and a marker can outlive a failed save. Dismissal is currently a local thread flag. See `ChatPane.jsx`, `chatPlans.js`, and `services/shaders.js`. | Give each plan revision a durable record. Claim a build with a unique revision key and expiring lease. Move to built in the same transaction as the acknowledged checkpoint. Store dismissal separately from deletion so its meaning is consistent across devices. | Start the same plan in two browsers simultaneously. Retry after an expired claim. Lose the save after code apply, reopen elsewhere, and see a recoverable state. |
| P1 | **External Figma publication.** The external create or update and local linkage are separate operations. A timeout or linkage failure can leave a remote shader without a local record. See `persistCurrentFigmaLink`, `figmaShadersWrite.js`, and `figma-shaders/index.ts`. | Persist an operation ID and intent before calling the provider. Record the returned remote ID before follow-up patching. Use provider idempotency if supported, otherwise reconcile unknown outcomes before permitting a second create. | Simulate provider success followed by a lost response or failed local write. Retry and recover the same remote shader. |
| P1 | **Chat and draft storage ownership.** Per-document thread keys live inside shared localStorage records. Whole-record writes can replace another tab’s independent update. The cloud plan and local plan can diverge during an offline edit or draft migration. | Persist record-level updates with stable message IDs and monotonic revisions. Serialize writers or use per-record IndexedDB transactions. Bind account-private data to account scope and define sign-out retention. Add explicit migration from shared records. | Edit two different threads from two tabs, close a stale tab last, and verify both histories remain. Clear a thread and verify a stale window cannot recreate it. |
| P1 | **User edits, code generation, and restore.** Automatic apply checks editor identity and baseline source. Deferred Apply and undo still rely on current UI state, and persisted source validity does not prove shader compilation or successful setup. Restore hydrates resources before changing the active runtime. | Tie offered edits, undo, repair, and restoration to a document revision. Stage and validate generated code in the intended runtime, then publish the source and its diagnostic outcome together. Preserve invalid manually edited code as a recoverable draft. | Change source, kind, or selected layer during a deferred apply or restore. Verify that stale work is blocked or offered with an explicit revision comparison. |

## State machines and the remaining transitions to exercise

The rows describe observable phases, the boundary that should own them, and the next regression tests. Pure rules belong in unit tests. Browser or service integration tests should run the transition with a delayed or failed dependency.

| Surface | States and ownership | Enforcement or test still needed |
| --- | --- | --- |
| Routes and document activation | Home, profile, editor, view, embed, and present are distinct modes. Document activation moves through identity resolution, persistence of the previous document, hydration, and ready or failed. Request generations already exist. | Use one route object for mode, identity and kind. Distinguish missing, inaccessible, offline, and failed dependencies. Test A → B → A, guest deep link followed by auth completion, Escape during a modal route change, and browser back during a failing save. |
| Local edits and autosave | Clean, dirty, saving, saved, retrying, conflict, and unavailable storage. Local visual media lives in IndexedDB while draft metadata lives in localStorage. | Use an acknowledged revision and a recoverable local buffer for cloud edits. Treat blocked or skipped writes as explicit outcomes. Test offline reload, quota failure, expired signed URLs, lock contention, backgrounding, and edits made while the tab is closing. |
| Versions | Unloaded, loading, empty, page ready, previewing, restoring, failed. Hover preview must never become the canonical edit. | Carry version and editor identities on each preview and restore request. Add real browser tests for hover exit during media hydration, restore while compiling, old snapshot schemas, and a page fetch failing after results are visible. |
| Library and profiles | Cold, cache hydrated, refreshing, fresh, stale, empty, failed. Auth scope owns private rows and signed links. | Decouple row readiness from thumbnail signing. Expose stale/error/empty separately and paginate the main library. Test error after cache hydration, thumbnail bucket changes, cache expiry, and account switch with pending requests. |
| Chat send and repair | Idle, assembling, streaming, stopping, validating, repairing, deferred, applied, interrupted, failed. Model discovery has its own loading and unavailable states. | Reserve message identity before async preprocessing and update by request ID. Scope attachments, undo and pending apply per document. Test double-send while splitting pasted code, stop then immediate send, provider switch with incompatible media, large attachments, and timeouts before first token. |
| Plan UI | Empty, drafting, interrupted, ready, building, built, dismissed and sync failed. Local Markdown, cloud Markdown, and build marker currently drive different pieces. | Use a single displayed plan state backed by the durable record above. Test cloud status lookup failure and focus refresh while a different revision is being written. |
| Dictation, uploads, and device inputs | Permission pending, recording, finishing, denied, disconnected or unavailable. Images, video, webcam, audio, HTML and fallback bitmap have separate lifecycles. | Use a document-scoped cancellation token across decode, permission, object URL and GPU upload. Dispose late arrivals. Test navigation during decode or permission, revoked camera, stalled media, unavailable codecs, and microphone handoff. |
| Code and WebGPU preview | Initializing, loading inputs, compiling, ready or showing last good output, paused, hidden, device lost, failed, disposed. | Expose which revision is rendering and why. Time-bound media startup. Handle device loss and successful recovery explicitly. Test rapid edits, invalid shaders, context loss, pointer cancel/leave, reduced motion, 1×/2× buffer changes, and reopen while a thumbnail capture is pending. |
| Composition and shader properties | Selection, enabled or disabled layers, loading dependencies, pending asset, unavailable asset, empty graph, ready. | Enforce role and stable layer identity at the document boundary. Surface absent resources per layer. Keep version-pinned and live dependency semantics explicit. Test reorder/remove while a control or upload is active, missing pinned sources, and stale composition thumbnails. |
| Responsive editor and popups | Wide, stacked, compact; library closed/opening/open/closing; panel collapsed, dragging or keyboard resizing. | Derive sizing rules and separator values from one measurement. Unify drag, key, persisted values, lost pointer capture and breakpoint transitions. Test composition separately on compact screens, short heights, high zoom, long titles, focus restoration and screen-reader values across states. |
| Export, view and Present | Validating, capturing, encoding, cancelling, failed, done; Present waits for the receiver and sends state and playback. | Model export as a job bound to an immutable snapshot. Cancel jobs on explicit request and release worker or media resources. Give Present a handshake timeout and validate message generation and ordering. Test popup blocked, disconnect/reconnect, hidden-tab export, codec fallback, cancellation and non-square sizing. |
| Account and Preferences | Signed out/loading/signed in; settings pristine/editing/saving/saved/failed; OAuth disconnected/connecting/connected/refreshing/revoked. | Clarify immediate versus Save-applied fields. Use one preference store with intentional cross-tab behavior and surfaced local failures. Separate profile save results from device key writes. Test editing during profile hydration, account change mid-save, blocked storage, and invalid/revoked Figma credentials. |
| Figma browsing and import | Disconnected/loading/ready/empty/error; import and push can be partial. | Bind request results to the active OAuth connection and the selected shader. Represent partial import with per-item results and safe retry. Verify using separate staging OAuth and Figma test files. |

The transactional publication, save, and plan changes should be validated together against a disposable Supabase project with two independent clients. OAuth, actual provider billing and streams, physical devices, encoding, and device-loss recovery need live or hardware-specific checks. The browser fixtures exercise the app flow with deterministic substitutes at these boundaries.
